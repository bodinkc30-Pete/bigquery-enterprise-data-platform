Phase 20 Failure / Recovery Evidence

2. A first exact-string transport patch was blocked by its guard because the expected function text did not match byte-for-byte. No file mutation occurred from that failed patch.
3. The bq transport was changed to pass SQL via stdin. A direct SELECT 1 probe returned exit 0 before runtime retry.
4. The first stdin runtime retry exceeded the remote tool response timeout. A live read-only probe afterwards showed 48 assets, 444 classified columns, 51 lineage edges, and zero controlled-test rows, proving the process had populated/recovered governance tables before the remote session ended.
5. Public runtime evidence/native-metadata files were not yet written after that timeout, so the runtime is rerun idempotently using DELETE→INSERT transactions to complete metadata labeling, marker-job capture, validation, and public evidence rather than falsely accepting the partial result.
6. The idempotent stdin rerun completed successfully.
